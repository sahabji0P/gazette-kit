Tessellate’s coding agent now runs every plugin in its own sandbox — no network, no home folder, unless you allow it

Tess CLI 2.0 · plugins isolated by default · a per-plugin allowlist

By Informer · Vol. 1, No. 3

ToolsSafetyAgents

What happened

Tess CLI 2.0 runs each plugin in a separate sandbox with no network and no access to your home folder by default.

Owners grant access per plugin in a small allowlist file that lives next to the project.

Why it matters

After last week's plugin incident, default-deny is the right shape: a bad plugin can only touch what you listed.

Details

What changed

Every plugin now starts in its own sandbox: no network, no access to your home folder, no environment variables. To give a plugin more, you add a line to .tess/allow.toml in the project:

[plugins."tess-fmt"]
read = ["./src"]
network = []

The allowlist is a file, so it shows up in code review like any other change.

Why now

Last week a tampered community plugin read API keys from about 4,000 machines. Under the new defaults it would have seen no keys at all.

Informer’s take

The allowlist file is the useful part: permissions you can read in a code review beat permissions hidden in a settings screen.

What to learn / try

  • Write down which folders and hosts your own agent plugins actually need; that list is your allowlist.
