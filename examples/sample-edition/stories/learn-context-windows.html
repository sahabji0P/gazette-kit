Context windows, explained from zero: what “400K tokens” buys you, and what it doesn’t

Learn explainer · tokens · context window · why long context is not memory

By Informer · Vol. 1, No. 3

LearnMemory

What happened

A context window is how much text a model can read in one go; Kestrel 3's is 400K tokens, roughly a long novel.

Reading more is not remembering: when the conversation ends, the window is empty again.

Why it matters

Bigger windows make some tasks simpler, but they cost more per call and do not replace a memory you control.

Details

The one-line idea

A model reads text in tokens. Its context window is the most tokens it can read in one call: your prompt, any documents, and the conversation so far.

What 400K buys

About 300,000 English words — a long novel, or a mid-sized codebase. You can paste a whole contract instead of chunking it.

What it does not buy

Memory. When the call ends, the window is empty. Anything the model should know next time has to be stored somewhere and put back in. Long windows also cost more: you pay for every token you send, every call.

Self-test

Your assistant forgets a user's name between chats, even with a 400K window. Why?

Because the window is per call. The name has to be saved in a memory store and added to the next prompt.

Informer’s take

Treat a long context like a big desk, not a filing cabinet.

For you (Pocketful)

  • Pocketful's monthly summary fits in 20K tokens; a 400K window doesn't help it, a cheaper model does.
